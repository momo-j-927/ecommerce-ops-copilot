# 架构与面试说明

## 请求链路

1. `route` 识别销售指标、异常扫描、知识检索或不明确请求。
2. 条件边把状态路由到对应工具节点。
3. 工具节点只返回结构化数据、来源和执行轨迹。
4. `compose` 生成可读答案。
5. 低置信度或无检索结果时，`review_required=true`，不伪造答案。

## 为什么第一版使用规则路由

第一版目标是建立可重复测试的基线。规则路由成本低、结果可解释，能让评测脚本稳定发现工作流问题。下一阶段接入 LLM 结构化输出后，应保留当前路由作为回退，并比较两种路由器的准确率、延迟和成本。

## 下一阶段

- 接入 OpenAI 兼容模型，并通过 Pydantic 约束意图和参数。
- 用真实公开电商数据替换合成数据，补充日期、渠道和商品维度。
- 为异常识别增加可配置阈值和人工确认接口。
- 将词法检索升级为 BM25 + 向量混合检索与 Rerank。
- 增加 50 条以上人工标注评测集、失败案例库和回归测试。
